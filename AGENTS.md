# Development notes

- The application was supplied as a Portuguese HTML/JavaScript prototype. It is now split into `index.html`, `styles.css`, and `app.js`; preserve the prototype's behavior unless a change is requested.
- Run `docker compose -f docker-compose.base44.yml up -d`. The frontend serves live checkout files on port 3000 with polling enabled; the node_modules volume is synchronized with `npm ci` on startup.
- Records use browser localStorage keys `appointments`, `patients`, `walkins`, `doctors`, and `clinicMessages`. There is no shared database or authentication. Use fictitious data only, including health histories; this is not suitable for real clinical records. Clearing browser storage removes records.
- The agenda starts on 2026-10-02 and renders saved appointments only, across a navigable seven-day window. The supplied dashboard still counts/lists all appointments despite its 'today' wording.
- Patient histories are captured in bookings/walk-ins and stored both on the visit and the matching patient (matching remains case-insensitive by name). Selecting an existing patient name prefills the current history. Profile dialogs are read-only.
- `server.js` runs as the internal `api` service; Vite proxies `/api` to it. It uses Node built-ins, no separate dependencies. GET `/api/config` reports only key presence and powers the configuration notice. POST `/api/messages` calls OpenAI with server-only `OPENAI_API_KEY` from the platform env file. No email/SMS delivery or real-person impersonation; replies are explicitly from an AI assistant.
- AI requests send only the typed recipient and message, never stored patient profiles. The message UI warns to use fictitious information. Key errors, rate limits, and upstream failures are shown honestly; no fake fallback replies. AI integration requires a valid key and provider balance. Global limit: ten requests/minute, two concurrent; no production auth is implemented.
- Fixed two startup blockers in the supplied code: the unclosed patient-search input and invalid apostrophe escaping. User text is escaped before HTML rendering.
- Verify startup with `curl -fsS http://localhost:3000/` and confirm the response contains `/@vite/client`. Run `docker compose -f docker-compose.base44.yml exec -T web npm run build` for compilation verification.
- Browser checks should cover agenda navigation and saved-booking slots, conditional history fields and persistence on both visits/patients, patient/doctor profile dialogs, message validation and real AI replies. Each created record should also appear in localStorage. Deletes use native confirmation dialogs and require confirmation during testing.
- When `OPENAI_API_KEY` is absent, `/api/config` must return `aiConfigured: false` and POST `/api/messages` must return a clear 503; do not claim real AI replies have been verified without provider credentials. Preview verification may report no browser tab; successful compilation and curl checks do not prove UI gestures.
